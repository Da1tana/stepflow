# План: запись действий (MVP)

Статус: **технический черновик, ожидает проверки API и согласования** · ветка `feat/recording-mvp` · дата: 2026-11-25

Цель: пользователь запускает запись, кликает по странице, видит шаги в боковой панели, останавливает запись, инструкция сохраняется локально. Без скриншотов.

## 1. Проверка ограничений (проведена на практике)

Эксперимент: Chromium 1.63 (Playwright) под Xvfb, расширение с `activeTab` + `scripting` и без host-разрешений, реальное нажатие `Alt+Shift+S` через X11 (XTest), затем `chrome.scripting.executeScript` из service worker.

| Ситуация | Результат |
|----------|-----------|
| Без действия пользователя | ❌ `Cannot access contents of the page` |
| После вызова расширения (горячая клавиша / иконка → popup) | ✅ доступ к активной вкладке |
| Переход на другую страницу **того же** origin | ✅ доступ сохраняется (скрипт нужно внедрить заново) |
| Переход на **другой** origin | ❌ доступ отозван |
| Возврат на исходный origin после этого | ❌ доступ не восстанавливается |
| Клик внутри **боковой панели** | ❌ `activeTab` **не выдаётся** |
| Синтетическое нажатие клавиш через CDP (`page.keyboard`) | ❌ не считается вызовом расширения |

Выводы:

1. **Запуск записи только из боковой панели с `activeTab` невозможен.** Клик в панели не даёт доступа к вкладке.
2. Рабочий запуск с минимальными разрешениями — **из popup** (клик по иконке или `Alt+Shift+S`). Открытие popup само выдаёт `activeTab`.
3. При переходе на другой сайт запись нужно приостанавливать и просить пользователя снова нажать на иконку.

## 2. Выбранная схема

**Разрешения:** `sidePanel`, `storage` (есть) + `activeTab`, `scripting`. Не добавлять `host_permissions`, `tabs`, `webNavigation`, `content_scripts` без отдельного обоснования и проверки.

**Запуск:**
- Popup → «Начать запись». Открытие панели и запуск записи должны выполняться из прямого пользовательского жеста там, где этого требуют API. Проверить, не теряется ли gesture при асинхронной передаче сообщения в service worker.
- Боковая панель → кнопка «Начать запись» не может получить доступ сама. Вместо неё панель показывает подсказку «Нажмите на иконку StepFlow или Alt+Shift+S». Во время записи в панели доступны «Стоп» и «Отменить».

**Безопасная альтернатива (по желанию, не в MVP по умолчанию):** `optional_host_permissions` для `http(s)://*/*`. Панель запрашивает доступ к **одному сайту** через `chrome.permissions.request` (диалог Chrome), а после остановки записи доступ снимается `chrome.permissions.remove`. Это позволит стартовать из панели и продолжать запись после перехода на другой сайт, но добавляет диалог разрешения и предупреждение в карточке расширения.

## 3. Поток данных

```
Popup ──start {tabId}──▶ SW ──executeScript(files)──▶ content/recorder.js (вкладка)
                          ▲                                   │ click (isTrusted, capture)
                          └──── recording/step {descriptor} ◀─┘ только описание элемента
SW: валидирует sender.tab.id, повторно очищает текст, строит название шага (core),
    пишет черновик в storage.local ──storage.onChanged──▶ Side panel (шаги вживую)
Stop/Cancel (popup или панель) ──▶ SW: сохраняет Guide в sf.guides или удаляет черновик
```

## 4. Конфиденциальность

Скрипт на странице отправляет только **описание элемента**: роль (`button`, `link`, `checkbox`, `textbox`…), безопасное видимое название (≤ 60 символов) и тип поля. Никогда:

- значения `input`, `textarea`, `select`, `contenteditable`, текст форм;
- что-либо из полей `type=password` (даже подпись заменяется на «поле пароля»);
- HTML, текст страницы, `document.title`, query-строку и hash URL (хранится только `origin + pathname`);
- синтетические события (`isTrusted === false`).

Вторая линия защиты в service worker должна чистить e-mail, последовательности из 4+ цифр и token-like strings, а также ограничивать длину. **Регулярные выражения не гарантируют безопасность:** сбор должен быть минимизирован на источнике, а подписи элементов проверены на утечки. Не отправлять произвольный текст страницы как fallback.

## 5. Названия шагов (i18n, en + ru)

| Элемент | Шаг |
|---------|-----|
| Кнопка / `role=button` / submit | Нажмите «Сохранить» |
| Ссылка | Перейдите по ссылке «Тарифы» |
| Флажок / переключатель | Нажмите на флажок «Запомнить меня» (без состояния) |
| Радио | Выберите вариант «Ежемесячно» |
| Выпадающий список | Откройте список «Страна» (без выбранного значения) |
| Текстовое поле | Нажмите на поле «Email» |
| Поле пароля | Нажмите на поле пароля |
| Вкладка / пункт меню | Откройте вкладку «…» / Выберите пункт меню «…» |
| Без названия | Нажмите на кнопку / ссылку |

Логика в `src/core/step-label.js` (чистая функция, переводчик передаётся параметром → unit-тесты в Node).

## 6. Надёжность

- **Состояние только в `chrome.storage.local`** (`sf.recording`: статус, tabId, origin, шаги). Перезапуск service worker ничего не теряет, все слушатели регистрируются синхронно.
- Запись шагов сериализуется очередью в SW (быстрые клики не теряются и не перетирают друг друга).
- **Навигация в той же вкладке:** проверить доступность `tabs.onUpdated` без `tabs` permission и доступность нужных полей объекта tab. Не запрашивать `tabs` permission заранее «на всякий случай». Повторно внедрять скрипт только при подтверждённом доступе.
- **Навигация на другой origin:** доступ `activeTab` отзывается; поставить запись на паузу и запросить повторное действие пользователя для выдачи доступа.
- **Закрытие вкладки** → черновик автоматически сохраняется как инструкция (если есть шаги).
- **Запуск браузера с незавершённым черновиком** (`runtime.onStartup`) → черновик сохраняется как инструкция, запись не возобновляется.
- **Отмена** → черновик удаляется без сохранения.
- **Запрещённые страницы** (`chrome://`, `chrome-extension://`, `edge://`, `about:`, `devtools://`, `view-source:`, Chrome Web Store, `data:`, PDF-просмотрщик) — проверка до внедрения (`core/restricted-url.js`) и понятная ошибка.
- Индикатор записи: бейдж `REC` на иконке (без разрешений), кратковременная подсветка кликнутого элемента, если включена настройка «Подсвечивать элементы».
- Ограничения MVP: только главный фрейм (без iframe), один активный сеанс.

## 8. Тесты

- **Unit:** названия шагов по всем ролям, обрезка и экранирование, очистка e-mail/цифр, запрещённые URL, переходы состояния записи.
- **E2E (headless):** тестовая сборка получает доступ к `http://127.0.0.1/*` (только в тестах, в `dist` не попадает) → старт, клики по кнопкам/ссылкам/полям, ввод пароля и текста (проверка, что их нет в хранилище целиком), переход на другую страницу того же сайта, перезапуск service worker посреди записи, остановка, отмена, закрытие вкладки, запрещённая страница, сохранение после повторного открытия панели.
- **E2E (реальный activeTab):** рабочая сборка без доп. разрешений, `Alt+Shift+S` через X11 → запись стартует; переход на другой origin → статус `paused`.
